# Aniverse Flip — стерео-карточки по аниме

Сайт-магазин: каталог карточек с вращением и переливом, конструктор своей карточки, форма заказа. Заказ уходит в Telegram через бота.

## Что внутри

- `site/` — сам сайт (HTML, CSS, JS, картинки, видео). Каталог, цены и контакты — в `site/data.js`.
- `serve.py` — сервер на чистом Python: отдаёт `site/` и принимает заказы на `POST /api/order`, пересылая их ботом в Telegram.

Статический хостинг (GitHub Pages и т. п.) не подойдёт: без `serve.py` заказы не будут отправляться.

## Запуск

```bash
python3 serve.py          # порт 8080
python3 serve.py 3000     # или свой порт
PORT=3000 python3 serve.py
```

Команда запуска для хостинга: `python3 serve.py` (порт берётся из переменной `PORT`, если хостинг её задаёт).

## Переменные окружения

| Переменная | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
| `TELEGRAM_CHAT_ID` | id чата, куда приходят заказы |
| `PORT` | порт (необязательно, по умолчанию 8080) |

Локально их можно положить в файл `.env` (образец — `.env.example`). Файл `.env` в репозиторий не коммитится.

Бот не отвечает на сообщения — он только присылает заказы. Получатель должен один раз нажать у бота «Start», иначе Telegram не даст боту написать первым.

## Карточки через бота

Влад отправляет боту два кадра карточки (можно одним альбомом), выбирает коллекцию кнопкой, пишет имя персонажа и выбирает версию. Карточка сохраняется в базе и сразу появляется на сайте. `/list` показывает добавленные через бота карточки и коллекции и позволяет их удалить, `/cancel` отменяет добавление.

**Новая коллекция:** `/collection` (или слово «коллекция») → название → рубашка (станет обложкой на сайте) → дальше присылай карточки по два кадра, они попадают в эту коллекцию, пока не нажмёшь «Закончить коллекцию». Адрес коллекции на сайте — `/catalog/c<номер>`.

- Нужна переменная `DATABASE_URL` (Postgres). Без неё сайт и заказы работают как раньше, просто без карточек из бота.
- Добавлять карточки может только чат из `TELEGRAM_CHAT_ID`.
- `SITE_URL` (необязательно) — ссылка на сайт в ответах бота.
- Бот опрашивает Telegram сам. Если сервер запущен в двух местах с одним токеном и базой, выключи опрос в одном из них: `BOT_POLLING=0`.

## Страницы

Сайт многостраничный, адреса отдаёт `serve.py`:

| Адрес | Файл | Что там |
|---|---|---|
| `/` | `site/index.html` | витрина коллекций, как это работает |
| `/catalog` | `site/catalog.html` | все коллекции |
| `/catalog/<коллекция>` | `site/collection.html` | карточки серии (id коллекции — из `data.js`) |
| `/builder` | `site/builder.html` | конструктор; принимает `?c=guts&r=special&q=2`, `?other=Имя&u=aot`, `?preset=common\|special\|photo` |
| `/how` | `site/how.html` | как это работает и вопросы (`/prices` переадресует сюда) |
| `/about` | `site/about.html` | о нас и видео |

Шапка, подвал, окна (корзина, избранное, меню, окно товара, оформление заказа) и подключение скриптов — общие, лежат в `site/partials/` и подставляются сервером вместо `<!--#include имя-->`. Менять их нужно в одном месте.

## Переписка через бота

Кнопки «Написать в Telegram» на сайте ведут в бота (`telegramBot` в `site/data.js`), а не в личку. Бот пересылает каждое сообщение покупателя в чат заказов (`TELEGRAM_CHAT_ID`) с именем покупателя. Чтобы ответить, сделай «Ответить» (reply) на пересланное сообщение — бот отправит ответ покупателю от своего имени, на твоём сообщении появится 👍.

## Отзывы

`/reviews` — все отзывы и форма (оценка 1–5, имя, текст, до 4 фото и одно видео до 30 МБ), на главной — три последних. Отзыв сразу виден на сайте; отзыв со ссылкой, @ником, фото или видео ждёт проверки (файлы приходят Владу в бот вместе с уведомлением). Владу в бот приходит карточка отзыва с кнопками «Ответить», «Скрыть» / «Опубликовать», «Удалить ответ». Ответить можно и просто ответом (reply) на карточку — ответ появится на сайте под отзывом от имени магазина. `/reviews` в боте — последние пять отзывов. С одного IP — не больше 3 отзывов в сутки. Код — `reviews.py`, нужна база (`DATABASE_URL`).

## Стандарт карточек

Любая карточка на сайте — строго формата 780×1051 (`--card-ratio`), ширину задаёт место, где она стоит; картинка любого размера (в том числе из бота) заполняет рамку по центру. Подписи переносятся и не растягивают карточку. Проверка — `tools/check-cards.mjs` (Playwright: WebKit как на iPhone и Chrome).

## Админка и записи сессий

Адрес — `/admin`. Нужна база (`DATABASE_URL`), таблицы создаются сами при первом обращении.

- **Вход по приглашениям.** Первое приглашение (роль «Владелец») выдаёт бот: Влад пишет ему `/admin` и получает одноразовую ссылку на 7 дней. Если бот недоступен: `DATABASE_URL=... python3 tools/admin_invite.py owner https://адрес-сайта`. Дальше приглашения создаются в разделе «Команда».
- **Роли.** Владелец — всё, включая роли и отключение доступа. Админ — меняет статусы заказов, удаляет записи, зовёт наблюдателей. Наблюдатель — только смотрит.
- **Сессии** — главное. Каждый визит записывается (`site/track.js` + rrweb из `site/vendor/`), в админке его можно посмотреть как видео: что человек видел, куда нажимал, как крутил карточки. Справа — лента действий: страницы, открытые карточки, корзина, оформление, заказ, поиск, ошибки JS; клик по событию перематывает запись. Сессию, которая идёт прямо сейчас, можно смотреть вживую (задержка несколько секунд).
- **Что не записывается:** всё, что вводят в поля (имя, контакт, комментарий, поиск видны звёздочками), фото покупателя в конструкторе, посещения ботов и автотестов. Записи хранятся 30 дней, события для статистики — 180.
- **Обзор** — посетители, заказы, конверсия, воронка (зашли → открыли карточку → корзина → оформление → заказ), источники (TikTok/Instagram/Telegram/UTM), популярные карточки, устройства, страны, что искали.
- **Заказы** — копия каждого заказа с сайта (как в Telegram) со статусом и кнопкой «Смотреть сессию».
- **Карточки** — какие открывают и сколько из них кладут в корзину.

Файлы: `admin.py` (сервер админки), `site/admin.html`, `site/admin/` (интерфейс), `site/track.js` (запись на сайте).
